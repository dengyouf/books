    MySQL主从复制

    主从复制原理

    主库把变更写进 binlog，从库拉过来重放一遍

            主库 (Master)                        从库 (Slave/Replica)
    ┌─────────────────┐                  ┌─────────────────────┐
    │  客户端写入      │                  │                     │
    │      ↓          │                  │   SQL Thread        │
    │  Binlog (二进制日志) │ ──网络传输──→ │      ↑              │
    │      ↑          │                  │  Relay Log (中继日志) │
    │  dump thread    │                  │      ↑              │
    └─────────────────┘                  │  IO Thread          │
                                         └─────────────────────┘
    步骤 作用
    第 1 步：主库产生 binlog 客户端执行 UPDATE users SET name='Tom' WHERE id=1;，主库在事务提交前把变更写入 binlog（sync_binlog=1 时刷盘）
    第 2 步：Dump 线程推送 主库的 dump 线程检测到 binlog 有新内容，把 event 推给从库的 IO 线程
    第 3 步：IO 线程写入 relay log 从库 IO 线程收到 event 后，先写入本地的 relay log（中继日志），并更新 master.info（记录已拉取到主库的哪个 binlog 位置）
    第 4 步：SQL 线程重放 从库 SQL 线程读取 relay log，解析成具体的 SQL 或行变更，在从库执行，并更新 relay-log.info（记录已重放到哪个位置）

    配置过程

    主库开启二进制日志 
    [mysqld]
# 主库的唯一标识，整数即可，集群内不能重复
server-id = 131
# 开启二进制日志，指定日志文件前缀（关键）
log-bin = mysql-bin
# 二进制日志格式，强烈建议使用 ROW 保证主从一致性
binlog_format = ROW

    必须重启 MySQL 服务使配置生效

    主库创建一个仅具备 REPLICATION SLAVE 权限的账号 
    CREATE USER 'repl'@'%' IDENTIFIED BY 'rootPwd@123';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';
FLUSH PRIVILEGES;

    对一个正在运行的服务器搭建主从复制的标准做法 
    # 使用mysqldump进行备份,然后恢复到从库，在根据坐标进行主从配置
mysqldump --source-data=2 --single-transaction \
  --routines --triggers --events \
  -u root -p \
  --all-databases > /tmp/full_backup.sql
# 将备份恢复到从库
mysql -uroot -prootPwd < full_backup.sql
# 获取主库二进制日志坐标
grep -o "SOURCE_LOG_FILE='[^']*'.*SOURCE_LOG_POS=[0-9]*" /tmp/full_backup.sql
SOURCE_LOG_FILE='binlog.000003', SOURCE_LOG_POS=858
    从库启动复制 

    select @@server_id;
+-------------+
| @@server_id |
+-------------+
|         133 |
+-------------+
# 告诉从库「主库是谁、用什么账号连、从哪个位点开始同步、要不要加密」
CHANGE REPLICATION SOURCE TO
  SOURCE_HOST='172.16.143.131',
  SOURCE_USER='repl',
  SOURCE_PASSWORD='rootPwd@123',
  SOURCE_LOG_FILE='mysql-bin.000003',
  SOURCE_LOG_POS=858,
  SOURCE_SSL=1;
# 启动从库的两个复制线程。
START REPLICA;
# 查看从库当前的复制状态
SHOW REPLICA STATUS\G
    | 参数 | 说明 | | --- | --- | |SOURCE_HOST|主库的 IP 地址 |SOURCE_USER|复制专用账号（之前 GRANT REPLICATION SLAVE 建的那个） |SOURCE_PASSWORD|该账号的密码 |SOURCE_LOG_FILE|从主库的哪个 binlog 文件开始读 |SOURCE_LOG_POS|从这个文件的哪个字节位置开始读 |SOURCE_SSL=1|使用 TLS 加密连接，解决 caching_sha2_password 的认证要求

    只要 Replica_IO_Running 和 Replica_SQL_Running 都是 Yes，且两个 Errno 都是 0，就说明主从复制正常

    备份恢复

    逻辑备份和恢复

    逻辑备份是 CREATE 和 INSERT 等SQL 语句

    mysqldump 的输出重定向到一个 .sql 文件

    • 简单、跨版本兼容性好、输出可读可编辑
    • 备份和恢复速度相对较慢，不适合超大规模数据
    参数 作用
    --databases 备份指定的数据库, 备份文件里已包含 CREATE DATABASE 和 USE 语句，恢复时不需要提前建库，也不用指定数据库名
    --all-databases 备份所有数据库，含 mysql 系统库，但通常不会备份 information_schema、performance_schema 和 sys 这几个库｜
    --ignore-table 排除掉不想导的库
    --single-transaction 对 InnoDB 表开启一致性快照，不锁表，不影响线上读写
    --no-data 只导出表结构，不导数据
    --quick 逐行读取，避免大表把内存撑爆
    --routines 备份存储过程、函数
    --events 备份存事件调度器
    --triggers 备份触发器
    备份单个数据库

    备份

    # 创建完全备份（基准）
xtrabackup --backup --target-dir=/data/backup/full
# 第一次增量：基于 full
xtrabackup --backup \
  --target-dir=/data/backup/inc1 \
  --incremental-basedir=/data/backup/full
# 第二次增量：基于 inc1
xtrabackup --backup \
  --target-dir=/data/backup/inc2 \
  --incremental-basedir=/data/backup/inc1
# 第三次增量：基于 inc2
xtrabackup --backup \
  --target-dir=/data/backup/inc3 \
  --incremental-basedir=/data/backup/inc2

    恢复

    # # 整理全量（只前滚，不回滚）
xtrabackup --prepare --apply-log-only --target-dir=/data/backup/full
# 合并 inc1（--apply-log-only : 它阻止的是未提交事务的回滚（rollback））
xtrabackup --prepare --apply-log-only \
  --target-dir=/data/backup/full \
  --incremental-dir=/data/backup/inc1
# 合并 inc2（--apply-log-only : 阻止的是未提交事务的回滚（rollback））
xtrabackup --prepare --apply-log-only \
  --target-dir=/data/backup/full \
  --incremental-dir=/data/backup/inc2

#合并 inc3（最后一次，去掉 apply-log-only，执行完整恢复）
xtrabackup --prepare \
  --target-dir=/data/backup/full \
  --incremental-dir=/data/backup/inc3

# 恢复备份
systemctl stop mysqld
rm -rf /var/lib/mysql/*   # 危险操作，确认路径
xtrabackup --copy-back --target-dir=/data/backup/full
chown -R mysql:mysql /var/lib/mysql
systemctl start mysqld
